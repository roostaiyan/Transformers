Two self-contained notebooks, each targeting a different domain:

| Notebook | Task | Dataset | Key technique |
|---|---|---|---|
| [`transformer_from_scratch.ipynb`](#-transformer_from_scratchipynb) | Language modelling | TinyStories | GloVe + SAM + Grokfast |

### Training stack

Three mechanisms that together create conditions for grokking on language data:

**1 — High weight decay (`λ = 1.0`)**  
L2 regularisation makes large-weight memorising solutions energetically expensive.  
*Power et al. (2022) showed grokking does not appear below a critical λ threshold.*

**2 — SAM · Sharpness-Aware Minimization (`ρ = 0.05`)**  
Two-step optimiser per batch:
```
SHOCK  — ε̂ = ρ · ∇L / ‖∇L‖₂   perturb weights to worst-case point
RELAX  — gradient at w + ε̂, restore w, AdamW step toward flat basin
```
Flat minima = generalising solutions; sharp minima = memorising solutions.  
SAM explicitly prefers the former (PAC-Bayes connection: flat basin → tight KL term).

**3 — Grokfast · slow-gradient amplification (`α = 0.98, λ = 2.0`)**  
```
g_slow ← α · g_slow + (1−α) · g     # EMA low-pass filter
g′     ← g + λ · g_slow              # amplify grokking-direction signal
```
During memorisation g_slow ≈ 0. As grokking begins, a persistent slow component  
builds up — Grokfast doubles its weight and compresses the generalisation transition.

### LR schedule

Linear warmup (300 steps) → cosine decay to `1e-5` over all training steps.  
No restarts — warm restarts re-spike LR and drive re-memorisation on small datasets.

### Dataset

**TinyStories** (Eldan & Li, 2023) — 2.1M short stories generated by GPT-3.5/GPT-4
using only the ~1 500 most common English words. We load ~500k characters (~90k word tokens)
in streaming mode from HuggingFace (no full download needed).

## 📓 `transformer_math_operations.ipynb`

Teaches a transformer to perform arithmetic and demonstrates **grokking** cleanly on
modular arithmetic — a controlled, verifiable setting where the transition from
memorisation to generalisation is unambiguous.

### Section map

```
Section 1    Math Tokenizer — character-level (digit tokens essential for carry/borrow)
Section 2    Infinite Data Generator — procedural, no fixed dataset
Section 3    Dataset — answer-only loss masking
Section 4    Transformer Model — GPT-style decoder with RoPE
Section 5    Training — 20 epochs, operator-split accuracy curves
Section 6    Testing on fresh problems
Section 7    Failure Analysis — where and why the model errs
Section 8    Attention Visualisation — which heads track digit positions
Section 9    The Grokking Phenomenon ★
             — Modular arithmetic (a + b mod 97)
             — Observing: train acc 100% → val acc ~0% → val acc jumps to ~100%
Section 10   Summary
```

### What the model learns

| Task | Mechanism discovered |
|---|---|
| Addition | Digit-by-digit right-to-left, carry propagation |
| Subtraction | Borrow propagation |
| Multiplication | Partial products (implicit × table) |
| Operator precedence | Early layers detect `*` and route differently |
| Algebra (`x + 3 = 7`) | Implicit two-step subtraction |
| Modular arithmetic | Fourier features (mechanistic interpretability) |

### ✅ Grokking achieved

On the modular arithmetic task (`a + b mod 97`, 50% train split, strong weight decay):

1. Training accuracy reaches **~100%** within a few epochs (memorisation)  
2. Validation accuracy stays near **0%** for many epochs  
3. Validation accuracy then **jumps sharply to ~100%** (grokking)

This is the canonical grokking result from Power et al. (2022), reproduced here from scratch.  
The `transformer_from_scratch_subword.ipynb` notebook applies the same principles (SAM + Grokfast + weight decay) to language data.
